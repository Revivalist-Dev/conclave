# Conclave — documentation map

Conclave keeps its own wiki here, under the project's `.cursor/`. Every page is symlinked into Zedon's
root wiki at [`.cursor/documents/conclave/`](../../../../.cursor/documents/conclave/) by
`node .cursor/tools/project-docs.mjs --sync`, so the root checker still walks them — and their links are
written relative to *this* directory, so nothing here breaks when a folder in the parent tree moves.

**This page is the map with the real descriptions. Start at the upgrade plan.**

## Plan

- [**Comprehensive upgrade plan**](./upgrade-plan.md) — the sequencing document, ordered
  robustness-first: make failures visible, correct the paths that exist, pin the supply chain, get one
  real run with a smoke test, then the MCP layer, then Proxima parity. Read this first.

## What the tree is

- [Conclave — provenance, layout, and the rename footprint](./conclave.md) — what the project is, how
  it is laid out, the four paths it references but does not contain, the rename from `brAInstorm` as
  applied (including the two identifier pairs that break silently if only one half moves), and where
  it diverges from real DanyAPI. Also records where the missing `crates/` sidecar source is **not**,
  so the "it only exists on the author's machine" claim is falsifiable.
- [Complete feature inventory](./features.md) — every feature read from the source rather than from
  `ARCHITECTURE.md`, with a working / partial / **stub** ledger at the end. The ledger is the useful
  half: it says what looks finished and is not.

## How it compares, and where it must go

- [Proxima comparison](./proxima-comparison.md) — feature by feature against `Zen4-bit/Proxima`,
  ending in a 26-capability gap list ordered by architectural weight. Item 1, provider routing, is the
  enabler for most of what follows.
- [MCP layer — implementation scaffold and roadmap](./mcp-roadmap.md) — what the MCP surface does
  today (two bridges, four tools), what the protocol requires as a checklist, a proposed tool surface,
  and the two traps this workspace has already measured: a bridge must handle a chunked response, and
  a failure must never be answered with silence.
- [Hardening and upgrades](./hardening-upgrades.md) — the defect findings behind the plan's early
  phases: correctness, failure visibility, security and supply chain, observability, developer
  experience. Each carries evidence, a proposed change, an effort, and **how to test that it worked**.
- [Wiring audit](./wiring-audit.md) — the cross-boundary class beside that page: strings, routes,
  identifiers and payload shapes that two independently written ends disagree about, which no unit test
  on either end can see. Nine boundary groups walked, the agreements recorded as well as the seven
  mismatches, and the two leads (the duplicated `docker compose up -d`, the hardcoded bootstrap database
  path) confirmed with evidence.

## Dependencies and the backend

- [Conclave dependency audit](./conclave-dependency-audit.md) — 25 declared dependencies measured live
  against npm, crates.io and PyPI: 17 current, 8 behind, all 8 breaking. Records the `typescript` cap
  at 6 (7 is published but both peers exclude it) and the three dependencies that sat in the wrong
  Cargo table and broke Windows linking.
- [DanyAPI review](./danyapi-review.md) — the backend's real route list, which of those routes conclave
  calls, where the two ends disagree, and the single-point-of-failure analysis for an unpinned image
  tag on a fork whose upstream has been deleted.
- [ConclaveAPI — the rebrand, what it takes to run, and the image](./conclaveapi-rebrand.md) — the
  three DanyAPI copies on this machine and which is newest, the 41 environment variables and nine real
  dependencies, everything that is not Python (the compiled solver, the JavaScript solvers, the WASM),
  the full rename footprint on both sides, how a provider is added today, and a diff of the three
  Dockerfiles including the capabilities Conclave's copy **lost**. Written 2026-10-15 because the
  upstream author deleted the original repository, so Conclave is about to own the tree.

**Read the plan when** you are starting upgrade work, and the feature inventory when you need to know
whether something is real. Both are regenerated by hand, not by a tool, so they carry a date.
