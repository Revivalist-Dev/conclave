# Conclave-owned version constraints for the DanyAPI provider image.
#
# The checkout's requirements.txt names seven packages with no version at all
# (`fastapi`, `uvicorn`, `httpx[socks]`, `pydantic`, `python-dotenv`, `pillow`,
# `python-multipart`). This file decides which version of each is installed, and
# which version of every package they pull in, so that
# `pip install -r requirements.txt -c constraints.txt` in
# provider-build/Dockerfile resolves to exactly these and a later `pip` cannot
# quietly take a newer one.
#
# The direct eight were read from the PyPI JSON API
# (https://pypi.org/pypi/<name>/json, `info.version`) on 2026-10-15:
#
#   fastapi          0.143.2
#   uvicorn           0.54.0
#   httpx             0.28.1
#   pydantic          2.14.1
#   python-dotenv     1.2.4
#   pillow            12.3.0
#   python-multipart  0.0.32
#   socksio           1.0.0    (the `socks` extra httpx[socks] pulls in)
#
# The remaining entries are the transitive closure the resolver chose for those
# eight, read back out of the built image with `pip freeze` on 2026-10-15. They
# are listed because a constraint file that pinned only the direct names would
# still let every transitive package float — `starlette`, `anyio` and
# `pydantic_core` included, which is where most of the behaviour lives.
